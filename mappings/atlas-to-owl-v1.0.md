Verified structural facts (all 2026.09, 0 exceptions):

- **Sub-techniques are expressed by `specializes`.** Every one of the 88
  `AML.T####.###` objects has exactly one `specializes` edge, its target is
  always a top-level technique, and the target id is always the source id
  without its last `.###` segment. No top-level technique has one.
- Every technique (120) and sub-technique (88) has ≥ 1 `achieves` edge
  (techniques: 112 × 1, 5 × 2, 3 × 3; sub-techniques: 82 × 1, 6 × 2); every
  tactic of a sub-technique is also a tactic of its parent.
- Every mitigation has ≥ 1 `mitigates` edge; 134 techniques/sub-techniques
  are mitigated.
- `maturity` ∈ {Feasible 24, Demonstrated 83, Realized 101}.
- `platforms` members ∈ {Enterprise 85, Predictive AI 82, Generative AI 106,
  Agentic AI 139}; 1–4 per technique (96 / 41 / 50 / 21).
- `categories` members ∈ {Policy 8, Technical - AI 21, Technical - Cyber 14}
  (2 mitigations have two); `lifecycle-phases` members ∈ {Business and Data
  Understanding, Data Preparation, AI Model Engineering, AI Model
  Evaluation, Deployment, Monitoring and Maintenance} (29 mitigations have
  more than one).
- Names are **not unique**: `Datasets`, `Models` and `AI Agent Tools` each
  name several sub-techniques. `atlasId` is the only key.
- `uuid` is unique across all 337 objects (not mapped; see Exclusions).

### The field that declares adaptation from ATT&CK: `attack-reference`

`attack-reference` is an optional attribute `{id, url}` of the ATLAS object
itself. It is the **only** field in format 6.0.0 that links ATLAS to ATT&CK
(there is no relationship type for it). STIX: the `external_references[]`
entry with `source_name = "mitre-attack"`, `external_id` = `id`
(62 = 44 + 14 + 4 in `stix-atlas.json`).

| On | Count | Target ids | Mapped in v1.0 |
| --- | --- | --- | --- |
| techniques | 44 (31 top-level, 13 sub-techniques) | 39 distinct: 31 `T####`, 8 `T####.###`; `T1596` ← 3, `T1595` ← 3, `T1211` ← 2 | **yes**, `ADAPTED_FROM` |
| tactics | 14 | 14 enterprise `TA####` (e.g. `AML.TA0002` → `TA0043`) | no (ADR-0004 Open question 3) |
| mitigations | 4 | `M1044`, `M1041`, `M1045`, `M1017` | no (KGCS has no ATT&CK mitigation class) |

Levels do not have to match: technique → technique 31, sub → sub 8,
sub → technique 5 (e.g. `AML.T0006.002` → `T1595`, `AML.T0011.003` →
`T1204`). Every `url` names its `id`; one (`AML.T0091.001` →
`https://attack.mitre.org/techniques/T1550/004`) has no trailing slash.

**Resolution against the live graph** (`kgcs-v11`, read-only, 2026-09-27):
38 of the 39 distinct targets exist, 30 as `Technique` and 8 as
`SubTechnique`, all with `domains = ["enterprise"]`. `T1656`
(Impersonation, cited by `AML.T0073`) is **not** in `kgcs-v11`: the loaded
ATT&CK bundles (`ATTCK=download:2026-09-06;modified-max:2026-08-04`) do not
contain it. On a chain equivalent to `kgcs-v11` the loader writes **43**
`ADAPTED_FROM` edges and reports **1 unresolved**.

## Transformation rules

1. **Pin the release.** Read `dist/v6/ATLAS-<release>.yaml` (or the release
   asset of tag `v<release>`), never the `ATLAS-latest.yaml` symlink. Record
   `ATLAS=<collection.version>` in `BuildMetadata.sourceSnapshots`
   (`build.shacl.ttl` v1.2).
2. **Classify techniques by `specializes`, not by id shape.** The two agree
   on 2026.09; if they ever disagree, fail the load.
3. **Order.** Load ATLAS after ATT&CK (`load_attck.py`): `ADAPTED_FROM` needs
   the ATT&CK nodes. Within ATLAS: tactics, techniques, sub-techniques,
   mitigations, then edges.
4. **`PART_OF` / `SUBTECHNIQUE_OF`** are `MERGE`d between ATLAS-labelled
   nodes only: `MATCH (a:AtlasTechnique {atlasId: $src}), (t:AtlasTactic {atlasId: $tgt})`.
   Never match an ATLAS id against an unlabelled pattern.
5. **`ADAPTED_FROM`.** Only for objects with `attack-reference`. Resolve
   `attack-reference.id` to `(:Technique {attackId})` for `T####` or
   `(:SubTechnique {attackId})` for `T####.###`, applying the shared v1.1
   bridge rule of `attck-to-owl-v1.0.md`: remap revoked targets along
   `revoked-by`, drop deprecated ones, drop unresolved ids; report
   remapped / dropped-deprecated / unresolved counts. Write the three edge
   properties verbatim. One edge per ATLAS object (the field is
   single-valued).
6. **Not loaded:** tactic and mitigation `attack-reference`, case studies,
   `employs`, `references[]`, `uuid`, `mitigates[].description` (Exclusions
   table in `mapping-coverage-matrix-v1.2.md`).
7. **Refresh.** ATLAS releases are monthly and edit objects in place
   (`modified-date`). The loader `MERGE`s on `atlasId` and `SET`s all
   properties; objects that disappear from a release are reported, not
   silently kept (ATLAS format 6.0.0 has no `revoked` / `deprecated` flag).

## Post-load invariants (session Q18)

```cypher
// counts = source profile (2026.09)
MATCH (n:AtlasTactic) RETURN count(n);                       // 16
MATCH (n:AtlasTechnique) RETURN count(n);                    // 120
MATCH (n:AtlasSubTechnique) RETURN count(n);                 // 88
MATCH (n:AtlasMitigation) RETURN count(n);                   // 40
MATCH (:AtlasTechnique|AtlasSubTechnique)-[r:PART_OF]->(:AtlasTactic) RETURN count(r);          // 225
MATCH (:AtlasSubTechnique)-[r:SUBTECHNIQUE_OF]->(:AtlasTechnique) RETURN count(r);              // 88
MATCH (:AtlasMitigation)-[r:MITIGATES]->(:AtlasTechnique|AtlasSubTechnique) RETURN count(r);    // 361
MATCH (:AtlasTechnique|AtlasSubTechnique)-[r:ADAPTED_FROM]->(:Technique|SubTechnique)
RETURN count(r);                                             // 44 - unresolved (43 on a kgcs-v11 chain)

// boundary: no edge between ATLAS and anything else except ADAPTED_FROM, outgoing
MATCH (a)-[r]-(b)
WHERE any(l IN labels(a) WHERE l STARTS WITH 'Atlas')
  AND NOT any(l IN labels(b) WHERE l STARTS WITH 'Atlas')
  AND NOT (type(r) = 'ADAPTED_FROM' AND startNode(r) = a)
RETURN count(r);                                             // 0

// every ADAPTED_FROM carries its provenance
MATCH ()-[r:ADAPTED_FROM]->()
WHERE r.sourceField <> 'attack-reference' OR r.attackReferenceId IS NULL OR r.attackReferenceUrl IS NULL
RETURN count(r);                                             // 0

// the ATT&CK counts do not move (label-qualified)
MATCH (:Technique)-[r:PART_OF]->(:Tactic) RETURN count(r);   // unchanged from the pre-ATLAS load (436 on kgcs-v11)
MATCH (:SubTechnique)-[r:SUBTECHNIQUE_OF]->(:Technique) RETURN count(r);  // unchanged (540)
```

**Unqualified counts change.** `MATCH ()-[r:PART_OF]->()` grows by 225 and
`MATCH ()-[r:SUBTECHNIQUE_OF]->()` by 88 once ATLAS is loaded. Any stats
minimum, snapshot export or equivalence check that counts these types
without labels must be qualified before `kgcs-v12` is compared with
`kgcs-v11` (ADR-0004, Consequences).
